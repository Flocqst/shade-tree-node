Does Tor drop? Yes, rarely, and never at the gate.

Forcing a brand-new rendezvous circuit on every one of 3903 requests, 4 dropped: 0.10%. All four were socks-fail, a Tor rendezvous circuit-build failure. None were the gate, and the proof of that is on the server: the gateway's DROP count did not move (it stayed at 35 from the earlier security run). A circuit that fails to build never delivers the request to the gateway, so these four never reached it. They are a Tor transport fact, not a gate rejection.
The four drops landed at 3m, 6m, 25m, and 27m. After minute 27, the run went the final 33 minutes and ~2000 requests with zero drops. So reliability did not degrade as circuits churned; if anything it settled.

Cold median is 4.95s, about 3x the warm path, because every request pays a full rendezvous build instead of reusing a circuit. 99% finished within 13s. There was one 46s outlier: a single circuit that struggled but completed rather than failing. This is the floor of the experience, not the typical one.

Real usage sits near the warm end: a Tor client reuses a rendezvous circuit for its lifetime, so most requests in a session ride a warm circuit. The cold numbers are the worst case you hit only if every request rebuilds from scratch. Even there, 99.90% land.

Corroboration and setup

egress, every success
all 3899 successful requests egressed from the gateway's clean IP, recorded per request. Not one used a different address.
gateway side
the gateway log gained ~3899 PASS over the run across 8 distinct nullifiers (8 members rotated). Its DROP count was unchanged, confirming the 4 failures were transport, not the gate.
isolation
SOCKS stream isolation (a unique credential per request) so Tor builds a separate circuit each time. Verified against a warm-circuit baseline.
proofs / budget
valid Semaphore proofs throughout (8 members), budget raised for the run so the rate limiter could not mask transport reliability, restored to 100 after
server
2 vCPU / 2 GB droplet, gateway + tor as systemd services, onion PoW defense on

The headline. Even in the worst case, a fresh Tor circuit built for every single request, the path delivered 99.90% of 3903 requests over a full hour, and every drop was an inherent Tor circuit-build failure that never reached the gateway, not a fault of the gate or the egress. Reliability held flat across the hour.

The honest cost is latency: cold requests run ~5s median because rebuilding a rendezvous is expensive. Normal usage reuses warm circuits and runs ~1.7s. Both numbers are real and both are in this report, so the reader can see the floor and the typical, not a cherry-picked best case.
